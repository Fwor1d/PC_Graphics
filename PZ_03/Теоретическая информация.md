# Теоретический материал или подсказки для практической работы № 3

### 1. Назначение работы

**Цель:** научиться представлять работу алгоритма как последовательность состояний и визуализировать эту последовательность в интерактивном приложении PyGame.

В рамках работы рассматриваются три алгоритма:

- пузырьковая сортировка;
- сортировка выбором;
- бинарный поиск.

---

## 2. Алгоритм и его визуализация — разные задачи

Обычная реализация алгоритма стремится получить результат как можно быстрее:

```python
data = [7, 3, 9, 2, 5]

# алгоритм

print(data)
```

При визуализации этого недостаточно. Приложению необходимо показать промежуточные состояния:

```text
исходные данные
      ↓
сравниваются элементы
      ↓
происходит обмен
      ↓
изменяется рабочая область
      ↓
следующее сравнение
      ↓
...
      ↓
результат
```

Следовательно, визуализатору нужен не только конечный результат, но и информация о том, **что именно алгоритм делает на текущем шаге**.

Удобно разделять систему так:

```text
АЛГОРИТМ
    │
    │ сообщает о новом шаге
    ↓
СОСТОЯНИЕ ВИЗУАЛИЗАЦИИ
    │
    ↓
PyGame RENDER
```

PyGame не должен определять, как работает сортировка. Алгоритм, в свою очередь, не должен знать координаты столбцов и цвета интерфейса.

---

## 3. Представление массива столбцами

Пусть имеется массив:

```python
values = [7, 3, 9, 2, 5]
```

Его можно представить графически:

```text
          █
  █       █
  █       █
  █       █       █
  █   █   █       █
  █   █   █       █
  █   █   █   █   █
  █   █   █   █   █
  █   █   █   █   █
 ───────────────────
  7   3   9   2   5
```

Если ширина рабочей области равна `area_width`, а количество элементов — `n`, ширина одного столбца может вычисляться так:

```python
bar_width = area_width / n
```

Масштабирование значения по высоте:

```python
height = value / max_value * max_bar_height
```

Так как координата `y` в PyGame увеличивается вниз, верхняя граница столбца:

```python
y = bottom_y - height
```

---

## 4. Цвет как часть визуального состояния

Один и тот же элемент массива может находиться в разных состояниях:

```text
обычный элемент       — нейтральный цвет
сравниваемый          — жёлтый
элемент для обмена    — красный
выбранный минимум     — оранжевый
отсортированный       — зелёный
граница поиска        — голубой
mid                    — фиолетовый
найденный элемент     — зелёный
исключённый элемент   — приглушённый
```

Важно: цвет — это **графическое представление состояния**, а не само состояние алгоритма.

Нежелательно помещать графику внутрь алгоритма:

```python
# плохо для разделения ответственности
color[i] = RED
```

Лучше вернуть смысл шага:

```python
{
    "type": "compare",
    "indices": (i, j),
}
```

А renderer уже решает, каким цветом это показать.

# 5. Пузырьковая сортировка

## 5.1. Идея

Пузырьковая сортировка многократно сравнивает соседние элементы:

```text
a[i] и a[i + 1]
```

Если они расположены в неправильном порядке, выполняется обмен.

Пример:

```text
[5, 2, 4, 1]

5 и 2 → обмен
[2, 5, 4, 1]

5 и 4 → обмен
[2, 4, 5, 1]

5 и 1 → обмен
[2, 4, 1, 5]
```

После первого полного прохода максимальный элемент оказывается справа. Поэтому его больше не требуется рассматривать на следующих проходах.

## 5.2. Базовая реализация

```python
def bubble_sort(values):
    n = len(values)

    for end in range(n - 1, 0, -1):
        for i in range(end):
            if values[i] > values[i + 1]:
                values[i], values[i + 1] = (
                    values[i + 1],
                    values[i],
                )
```

Обычная функция выполняет сортировку полностью и возвращает управление только после завершения. Для визуализации этого недостаточно.

## 5.3. Оптимизация раннего завершения

Если во время прохода не произошло ни одного обмена, массив уже отсортирован:

```python
swapped = False

for i in range(end):
    if values[i] > values[i + 1]:
        values[i], values[i + 1] = values[i + 1], values[i]
        swapped = True

if not swapped:
    break
```

## 5.4. Сложность

```text
средний случай: O(n²)
худший случай:  O(n²)
лучший случай:  O(n) при раннем завершении
память:         O(1)
```

# 6. Сортировка выбором

## 6.1. Идея

Сортировка выбором делит массив на две части:

```text
[ отсортированная часть | неотсортированная часть ]
```

На каждом шаге:

1. выбирается начало неотсортированной области;
2. в оставшейся части находится минимальный элемент;
3. минимум меняется местами с первым элементом рабочей области.

Пример:

```text
[5, 2, 4, 1]

минимум = 1
↓
[1, 2, 4, 5]

теперь рассматриваем:
   [2, 4, 5]
```

## 6.2. Базовая реализация

```python
def selection_sort(values):
    n = len(values)

    for i in range(n - 1):
        min_index = i

        for j in range(i + 1, n):
            if values[j] < values[min_index]:
                min_index = j

        values[i], values[min_index] = (
            values[min_index],
            values[i],
        )
```

При визуализации следует различать:

```text
i          — позиция, куда должен попасть минимум
j          — текущий проверяемый элемент
min_index  — лучший минимум, найденный к этому моменту
```

## 6.3. Сложность

```text
лучший случай:  O(n²)
средний случай: O(n²)
худший случай:  O(n²)
```

Количество обменов значительно меньше, чем у пузырьковой сортировки: не более порядка `O(n)`.

# 7. Генераторы для пошагового выполнения

Обычный вызов:

```python
bubble_sort(values)
```

даст визуализатору только готовый результат.

Для пошагового выполнения удобно использовать генератор и `yield`.

Простой пример:

```python
def counter():
    yield 1
    yield 2
    yield 3
```

Создание генератора:

```python
generator = counter()
```

Получение следующего состояния:

```python
next(generator)
```

Таким образом PyGame может выполнять один алгоритмический шаг за заданный интервал времени.

---

# 9. Шаг алгоритма как данные

Удобно возвращать описание текущего шага.

Сравнение:

```python
yield {
    "type": "compare",
    "indices": (i, i + 1),
}
```

Обмен:

```python
yield {
    "type": "swap",
    "indices": (i, i + 1),
}
```

Найден новый минимум:

```python
yield {
    "type": "new_min",
    "indices": (min_index,),
}
```

Renderer получает структуру состояния и отображает её.

# 10. Неполный пример генератора Bubble Sort

Следующий код показывает принцип, но не является готовым решением практической работы:

```python
def bubble_sort_steps(values):
    n = len(values)

    for end in range(n - 1, 0, -1):
        swapped = False

        for i in range(end):
            yield {
                "type": "compare",
                "indices": (i, i + 1),
            }

            if values[i] > values[i + 1]:
                values[i], values[i + 1] = (
                    values[i + 1],
                    values[i],
                )

                swapped = True

                yield {
                    "type": "swap",
                    "indices": (i, i + 1),
                }

        if not swapped:
            break
```

# 11. Выполнение генератора в PyGame

Нельзя выполнять весь генератор внутри одного кадра:

```python
while sorting:
    next(generator)
```

Нужен контролируемый интервал между шагами:

```python
step_timer += dt

if running_algorithm and step_timer >= step_interval:
    step_timer = 0

    try:
        current_step = next(generator)
    except StopIteration:
        running_algorithm = False
```

Здесь:

```text
dt             — длительность предыдущего кадра;
step_interval  — интервал между шагами;
current_step   — текущее состояние визуализации.
```

---

# 12. Скорость визуализации

Пусть:

```python
steps_per_second = 10
```

Тогда:

```python
step_interval = 1.0 / steps_per_second
```

Например:

```text
5 шагов/с
10 шагов/с
30 шагов/с
60 шагов/с
```

Это скорость алгоритмической анимации, а не FPS окна.

# 13. Пауза и пошаговый режим

Удобно использовать состояния:

```text
IDLE
RUNNING
PAUSED
FINISHED
```

При паузе:

```text
рендер продолжается;
события продолжают обрабатываться;
генератор не получает следующий next().
```

Для разбора алгоритма удобно предусмотреть:

```text
N — выполнить один шаг
```

# 14. Статистика алгоритма

Визуализатор может хранить:

```python
comparisons = 0
swaps = 0
steps = 0
```

Важно различать эти величины. Один визуальный шаг не обязательно равен одной элементарной операции алгоритма.

# 15. Бинарный поиск

## 15.1. Условие применения

Бинарный поиск работает по **упорядоченной последовательности**.

```python
values = [3, 7, 10, 14, 18, 21, 30]
```

Для произвольно перемешанного массива стандартный бинарный поиск неприменим.

## 15.2. Основная идея

Используются три позиции:

```text
left
right
mid
```

Средний индекс:

```python
mid = (left + right) // 2
```

После сравнения `values[mid]` с искомым значением примерно половина диапазона исключается из дальнейшего рассмотрения.

---

# 16. Один шаг бинарного поиска

Ищем `21`:

```text
индекс:   0   1   2   3   4   5   6
значение: 3   7  10  14  18  21  30
```

Первый шаг:

```text
left = 0
right = 6
mid = 3
values[3] = 14
```

Так как `14 < 21`, обновляем:

```python
left = mid + 1
```

Остаётся диапазон:

```text
[18, 21, 30]
```

---

# 17. Базовая реализация бинарного поиска

```python
def binary_search(values, target):
    left = 0
    right = len(values) - 1

    while left <= right:
        mid = (left + right) // 2

        if values[mid] == target:
            return mid

        if values[mid] < target:
            left = mid + 1
        else:
            right = mid - 1

    return -1
```

Для визуализации необходимо показывать изменение `left`, `mid`, `right` и исключённую область.

---

# 18. Сложность бинарного поиска

После каждого шага размер рассматриваемой области примерно уменьшается вдвое:

```text
n
n / 2
n / 4
n / 8
...
```

Поэтому:

```text
O(log n)
```

Для сравнения линейный поиск имеет сложность `O(n)`.

Однако преимущество бинарного поиска возникает только на уже отсортированных данных. Если перед единственным поиском необходимо сначала сортировать исходный массив, стоимость сортировки тоже следует учитывать.

---

# 19. Визуализация бинарного поиска

Следует визуально различать:

```text
активный диапазон [left, right]
mid
исключённые элементы
найденный элемент
```

Пример:

```text
исключено      активный диапазон
    ↓                  ↓
[3, 7, 10] | [14, 18, 21, 30]
                ↑
               mid
```

# 20. Генератор бинарного поиска

Принцип аналогичен сортировкам:

```python
def binary_search_steps(values, target):
    left = 0
    right = len(values) - 1

    while left <= right:
        mid = (left + right) // 2

        yield {
            "type": "check",
            "left": left,
            "right": right,
            "mid": mid,
        }

        # дальнейшая логика поиска
```

Алгоритм сообщает визуализатору текущее состояние. Renderer не должен вычислять `mid` самостоятельно.

# 21. Значение отсутствует

Если после нескольких шагов возникает:

```python
left > right
```

искомое значение отсутствует.

Визуализатор должен показывать это как нормальное конечное состояние, а не как ошибку приложения.

---

# 22. Повторяющиеся элементы

Для массива:

```python
values = [2, 4, 4, 4, 7, 9]
```

обычный бинарный поиск может вернуть любой индекс, содержащий `4`.

Если требуется первое или последнее вхождение, алгоритм модифицируется. Для основной работы достаточно поиска одного совпадения.

# 25. Функция отрисовки

Логически renderer может выглядеть так:

```python
def draw_array(screen, values, step):
    ...
```

Внутри допустимы графические операции:

```python
pygame.draw.rect(...)
font.render(...)
screen.blit(...)
```

Нежелательно изменять внутри `draw_array()` массив, счётчики сравнений, состояние генератора и индексы алгоритма.
