# Практическая работа
## Визуализация алгоритмов поиска пути в PyGame

### 1. Цель работы

Разработать интерактивное приложение на **Python + PyGame**, позволяющее создавать двумерную сеточную карту и пошагово визуализировать работу алгоритмов поиска пути.

В рамках работы необходимо реализовать:

- поиск в ширину **BFS**;
- алгоритм **Dijkstra**;
- алгоритм **A\***;
- восстановление найденного маршрута;
- пошаговую визуализацию состояния алгоритма

Работа должна показывать не только итоговый путь, но и **процесс поиска**.

---

## 2. Общая постановка задачи

Необходимо создать приложение с двумерным полем, состоящим из клеток.

Пользователь должен иметь возможность:

1. задать стартовую клетку;
2. задать целевую клетку;
3. создавать и удалять препятствия;
4. для Dijkstra и A* задавать клетки с повышенной стоимостью перемещения;
5. выбирать алгоритм поиска;
6. запускать, приостанавливать и выполнять алгоритм пошагово;
7. наблюдать исследуемые клетки и итоговый маршрут;
8. сравнивать результаты разных алгоритмов.

Пример логической карты:

```text
S . . . # . . .
. # # . # . . .
. . . . . . # .
. # . # # . # .
. . . . . . . G
```

где:

```text
S — старт
G — цель
# — препятствие
. — доступная клетка
```

---

## 3. Требования к окну приложения

Создать окно размером не менее:

```text
1200 × 750
```

Интерфейс должен содержать:

- сеточную карту;
- панель управления;
- название выбранного алгоритма;
- легенду состояний клеток;
- статистику текущего запуска;
- подсказку по управлению.

Приложение должно корректно завершаться через `Esc` и кнопку закрытия окна.

---

## 4. Сетка и состояния клеток

Создать двумерную сетку размером ориентировочно 20–35 строк и 30–50 столбцов.

Каждая клетка должна иметь логические координаты:

```python
(row, col)
```

и экранный прямоугольник:

```python
pygame.Rect(...)
```

Минимальный набор состояний:

```text
EMPTY      — свободная клетка
WALL       — препятствие
START      — начальная точка
GOAL       — цель
OPEN       — клетка добавлена во frontier
CLOSED     — клетка уже обработана
PATH       — клетка итогового маршрута
WEIGHTED   — клетка с повышенной стоимостью
```

Все состояния должны визуально различаться. В интерфейсе должна быть легенда цветов.

---

## 5. Редактирование карты

Реализовать интерактивное редактирование мышью.

Например:

```text
ЛКМ        — создать препятствие
ПКМ        — удалить препятствие
S + ЛКМ    — установить START
G + ЛКМ    — установить GOAL
W + ЛКМ    — установить клетку с повышенной стоимостью
```

Допускается другой набор управления, если он указан в интерфейсе.

Требования:

- START и GOAL не могут находиться в одной клетке;
- препятствие нельзя поставить поверх START и GOAL;
- взвешенная клетка остаётся проходимой;
- после изменения карты предыдущие OPEN/CLOSED/PATH должны сбрасываться.

---

## 6. Модель соседей

Для основной части работы использовать движение по четырём направлениям:

```text
↑ ↓ ← →
```

Смещения:

```python
(-1, 0)
(1, 0)
(0, -1)
(0, 1)
```

Создать отдельную функцию:

```python
def get_neighbors(node, grid):
    ...
```

Она должна учитывать границы карты и исключать препятствия.

---

## 7. BFS

Реализовать поиск в ширину.

BFS должен:

1. начинать поиск из START;
2. использовать очередь;
3. не посещать одну клетку повторно;
4. сохранять информацию для восстановления маршрута;
5. завершаться при достижении GOAL;
6. корректно завершаться при отсутствии пути.

Визуализация должна показывать `OPEN`, `CLOSED` и `PATH`.

---

## 8. Пошаговое выполнение

Алгоритм должен выполняться непосредственно во время визуализации.

Не допускается вариант:

```text
полностью выполнить алгоритм
↓
сохранить все состояния
↓
затем проиграть готовую анимацию
```

Рекомендуемый интерфейс:

```python
def bfs_steps(...):
    yield step
```

Например:

```python
{
    "type": "visit",
    "node": current,
}
```

---

## 9. Восстановление маршрута

При переходе к новой клетке сохранять предшественника:

```python
came_from[next_node] = current
```

После достижения GOAL восстановить маршрут от цели к старту и показать его отдельным цветом.

START и GOAL должны сохранять собственные обозначения.

---

## 10. Dijkstra

Реализовать алгоритм Dijkstra.

Минимум два типа проходимых клеток:

```text
обычная клетка       — стоимость 1
взвешенная клетка    — стоимость 5
```

Алгоритм должен учитывать накопленную стоимость маршрута.

Для frontier использовать приоритетную очередь:

```python
import heapq
```

Визуализация должна показывать, что более длинный по числу клеток маршрут может иметь меньшую стоимость.

---

## 11. A*

Реализовать A*.

Для движения по четырём направлениям использовать Manhattan distance:

```python
def heuristic(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1])
```

Приоритет вершины должен определяться через накопленную стоимость и эвристику.

Визуализация должна позволять увидеть более направленный характер поиска A* по сравнению с Dijkstra.

---

## 12. Переключение алгоритмов

Реализовать:

```text
1 — BFS
2 — Dijkstra
3 — A*
```

При переключении:

- сама карта сохраняется;
- START, GOAL, WALL, WEIGHTED сохраняются;
- OPEN, CLOSED и PATH очищаются.

---

## 13. Управление выполнением

Минимум:

```text
SPACE — Start / Pause
N     — один шаг
R     — очистить результат поиска
C     — очистить карту
↑     — увеличить скорость
↓     — уменьшить скорость
Esc   — выход
```

Пауза должна останавливать только алгоритмические шаги, но не event loop PyGame.

---

## 14. Статистика

Для каждого запуска отображать:

```text
Algorithm
Visited nodes
Path length
Path cost
Steps
Search status
```

Дополнительно допускается:

```text
Frontier size
Search time
```

При этом визуализационное время не следует считать основным показателем эффективности алгоритма.

---

## 15. Отсутствие пути

Если GOAL недостижима, приложение должно вывести:

```text
Path not found
```

и корректно перейти в завершённое состояние.

## 16. Архитектура проекта

Минимальная структура:

```text
practice_pathfinding/
├── main.py
├── algorithms.py
├── grid.py
├── visualizer.py
├── settings.py
├── README.md
└── screenshots/
```

Назначение:

```text
main.py
    event loop и управление приложением

algorithms.py
    BFS, Dijkstra, A*, heuristic

grid.py
    сетка, соседи, стоимости, редактирование

visualizer.py
    отрисовка карты, состояний и статистики

settings.py
    константы, цвета, размеры, скорость
```

`algorithms.py` не должен импортировать PyGame.

Алгоритмы работают с логическими данными, а PyGame отвечает за ввод, анимацию и отображение.

## 17. Обязательные тестовые сценарии

Проверить:

1. START и GOAL находятся рядом;
2. карта без препятствий;
3. несколько возможных маршрутов;
4. GOAL полностью окружена WALL;
5. короткий дорогой путь и длинный дешёвый путь;
6. START и GOAL находятся далеко друг от друга.
