### 2. Теоретический минимум

#### 2.1. Главное отличие интерактивного приложения от обычного скрипта

Обычный скрипт, как правило, выполняется последовательно:

```text
получить данные → выполнить вычисления → вывести результат → завершиться
```

Графическое интерактивное приложение работает иначе. После создания окна оно многократно повторяет один и тот же цикл:

```text
обработать события
        ↓
прочитать ввод
        ↓
изменить состояние
        ↓
нарисовать новый кадр
        ↓
показать кадр
        ↓
повторить
```

Такой цикл обычно называют **главным циклом приложения** или **game loop**.

Окно должно продолжать обрабатывать события операционной системы даже в тот момент, когда пользователь ничего не нажимает.

---

#### 2.2. Инициализация PyGame и создание окна

Минимальная подготовка приложения:

```python
import pygame

pygame.init()

WINDOW_WIDTH = 1000
WINDOW_HEIGHT = 650

screen = pygame.display.set_mode((WINDOW_WIDTH, WINDOW_HEIGHT))
pygame.display.set_caption("Bakery Simulator")

clock = pygame.time.Clock()
```

`pygame.init()` инициализирует основные подсистемы библиотеки.

`pygame.display.set_mode(...)` создаёт окно и возвращает объект `Surface`, представляющий область, в которую выполняется отрисовка.

`pygame.time.Clock()` используется для контроля частоты кадров и измерения времени между кадрами.

---

#### 2.3. Экранная система координат

В PyGame начало координат находится в левом верхнем углу окна.

```text
(0, 0) ───────────────────────────→ x
   │
   │
   │
   │
   ↓
   y
```

Следовательно:

- увеличение `x` перемещает объект вправо;
- уменьшение `x` — влево;
- увеличение `y` — вниз;
- уменьшение `y` — вверх.

Для точки:

```python
x = 250
y = 180
```

координата `x` задаёт положение по горизонтали, а `y` — по вертикали.

### 3. Основной цикл приложения

Базовый вариант:

```python
running = True

while running:
    dt = clock.tick(60) / 1000.0

    for event in pygame.event.get():
        if event.type == pygame.QUIT:
            running = False

    screen.fill((245, 240, 230))

    pygame.display.flip()

pygame.quit()
```

Здесь:

- `pygame.event.get()` получает накопившиеся события;
- `pygame.QUIT` возникает при попытке закрыть окно;
- `screen.fill(...)` очищает кадр;
- `pygame.display.flip()` показывает новый кадр;
- `pygame.quit()` корректно завершает работу библиотеки.

```
Важно
pygame.display.flip() показывает результат отрисовки текущего кадра.
Если изменять Surface, но не вызывать flip(), пользователь не увидит новый кадр.
```

### 4. Частота кадров и delta time

Вызов:

```python
dt = clock.tick(60) / 1000.0
```

решает две задачи:

1. ограничивает частоту примерно 60 кадрами в секунду;
2. возвращает длительность предыдущего кадра.

После деления на 1000 величина `dt` измеряется в секундах.

Если скорость объекта равна:

```python
speed = 240
```

это удобно интерпретировать как **240 пикселей в секунду**.

Перемещение:

```python
x += speed * dt
```

делает движение значительно менее зависимым от фактического FPS.

Нежелательный вариант:

```python
x += 5
```

Здесь объект перемещается на 5 пикселей **каждый кадр**, поэтому его реальная скорость зависит от частоты кадров.

### 5. Дискретные события и непрерывный ввод

В PyGame есть два принципиально разных случая.

#### 5.1. Действие один раз при нажатии

Для действий типа:

- открыть меню;
- изменить цвет;
- подтвердить выбор;
- поставить игру на паузу;

удобно использовать `KEYDOWN`.

```python
for event in pygame.event.get():
    if event.type == pygame.KEYDOWN:
        if event.key == pygame.K_SPACE:
            print("Пробел нажат")
```

Такое действие выполняется один раз при возникновении события.

#### 5.2. Действие всё время, пока клавиша удерживается

Для движения удобнее использовать:

```python
keys = pygame.key.get_pressed()

if keys[pygame.K_w]:
    ...
if keys[pygame.K_s]:
    ...
if keys[pygame.K_a]:
    ...
if keys[pygame.K_d]:
    ...
```

`pygame.key.get_pressed()` возвращает текущее состояние клавиатуры.

```
Практическое правило

KEYDOWN:
дискретное действие — один раз на нажатие.

pygame.key.get_pressed():
непрерывное действие — выполняется всё время удержания клавиши.
```

### 6. Вектор движения

Для удобного движения по двум координатам можно использовать `pygame.Vector2`.

```python
position = pygame.Vector2(200, 300)
direction = pygame.Vector2(0, 0)
```

Формирование направления:

```python
keys = pygame.key.get_pressed()

direction.update(0, 0)

if keys[pygame.K_w]:
    direction.y -= 1
if keys[pygame.K_s]:
    direction.y += 1
if keys[pygame.K_a]:
    direction.x -= 1
if keys[pygame.K_d]:
    direction.x += 1
```

При движении по диагонали длина вектора `(1, 1)` больше длины `(1, 0)`.

Поэтому перед использованием направление удобно нормализовать:

```python
if direction.length_squared() > 0:
    direction = direction.normalize()
```

После этого:

```python
position += direction * speed * dt
```

скорость движения по диагонали остаётся примерно такой же, как по горизонтали и вертикали.

### 7. Рисование графических примитивов

PyGame позволяет рисовать основные фигуры через `pygame.draw`.

#### Круг

```python
pygame.draw.circle(
    screen,
    (70, 130, 220),
    (round(position.x), round(position.y)),

```

#### Прямоугольник

```python
counter_rect = pygame.Rect(350, 120, 420, 100)

pygame.draw.rect(
    screen,

```

#### Рамка

```python
pygame.draw.rect(
    screen,
    (60, 60, 60),
    counter_rect,
    width=2,

```

Цвет задаётся RGB-кортежем:

```python
(R, G, B)
```

где компоненты обычно находятся в диапазоне `0...255`.

### 9. Область взаимодействия

Необязательно требовать, чтобы объект физически пересекал другой объект. Можно создать отдельную невидимую зону перед ним.

```python
interaction_rect = pygame.Rect(380, 225, 360, 70)
```

Положение клиента можно представить небольшим прямоугольником:

```python
client_rect = pygame.Rect(0, 0, 40, 40)
client_rect.center = (round(position.x), round(position.y))
```

Проверка:

```python
can_interact = client_rect.colliderect(interaction_rect)
```

Если `can_interact == True`, интерфейс может показать подсказку:

```text
E — взаимодействовать
```

### 10. Простая проверка столкновения

Для небольшого учебного проекта достаточно следующего подхода:

1. вычислить предполагаемую новую позицию;
2. построить прямоугольник объекта в новой позиции;
3. проверить пересечение с препятствиями;
4. принять или отклонить движение.

Пример:

```python
next_position = position + direction * speed * dt

next_rect = pygame.Rect(0, 0, 40, 40)
next_rect.center = (round(next_position.x), round(next_position.y))

blocked = any(next_rect.colliderect(rect) for rect in obstacles)

if not blocked:
    position = next_position
```

`obstacles` может содержать прямоугольники прилавка, кассы и других непроходимых объектов.

Для данной работы сложная физика столкновений не требуется.

### 11. Ограничение объекта границами окна

Если радиус клиента известен:

```python
radius = 24
```

положение центра можно ограничить:

```python
position.x = max(radius, min(WINDOW_WIDTH - radius, position.x))
position.y = max(radius, min(WINDOW_HEIGHT - radius, position.y))
```

Так объект не сможет полностью или частично выйти за границы окна.

### 13. Состояние приложения

Интерактивное приложение постоянно хранит некоторое **состояние**.

Например:

```python
money = 420
current_order = None
order_state = "NO_ORDER"
message = ""
```

Графика должна отображать это состояние, а действия пользователя — изменять его.

Удобно рассматривать приложение как связь:

```text
событие пользователя
        ↓
изменение состояния
        ↓
новое визуальное представление
```

Например:

```text
пользователь выбрал кофе
        ↓
money уменьшается
order_state становится WAITING
        ↓
на экране появляется таймер приготовления
```

### 15. Проверка возможности заказа

Для выбранного товара логика может проверять несколько условий.

```python
if product["stock"] <= 0:
    message = "Товар закончился"

elif money < product["price"]:
    message = "Недостаточно денег"

else:
    money -= product["price"]
    product["stock"] -= 1
```

Это уже не графическая операция. Это изменение **состояния предметной области**.

PyGame нужен здесь для ввода и визуального отображения результата.

### 16. Состояния заказа

Для учебной симуляции удобно использовать конечный набор состояний:

```python
NO_ORDER = "NO_ORDER"
WAITING = "WAITING"
READY = "READY"
DONE = "DONE"
```

Пример переходов:

```text
NO_ORDER
   │
   │ заказ продукта без приготовления
   ├──────────────────────────────→ READY
   │
   │ заказ продукта с приготовлением
   ↓
WAITING ─────────→ READY ─────────→ DONE
```

Состояние позволяет не смешивать в одном условии все возможные ситуации.

### 17. Таймер без time.sleep()

В интерактивном приложении нежелательно выполнять:

```python
import time
time.sleep(5)
```

На это время программа перестаёт обновлять окно и обрабатывать события.

Вместо остановки приложения следует хранить оставшееся время:

```python
cooking_left = 5.0
order_state = WAITING
```

И уменьшать его на каждом кадре:

```python
if order_state == WAITING:
    cooking_left -= dt

    if cooking_left <= 0:
        cooking_left = 0
        order_state = READY
```

Пока таймер уменьшается, приложение продолжает:

- обрабатывать клавиатуру;
- перемещать клиента;
- перерисовывать сцену;
- реагировать на закрытие окна.

### 18. Полоса прогресса

Если известно полное время приготовления:

```python
cook_time = 5.0
```

и оставшееся:

```python
cooking_left = 2.0
```

прогресс:

```python
progress = 1.0 - cooking_left / cook_time
progress = max(0.0, min(1.0, progress))
```

Если ширина всей полосы:

```python
bar_width = 240
```

то ширина заполненной части:

```python
filled_width = int(bar_width * progress)
```

Отрисовать можно двумя прямоугольниками:

```python
pygame.draw.rect(screen, (210, 210, 210), (x, y, bar_width, 20))
pygame.draw.rect(screen, (70, 170, 90), (x, y, filled_width, 20))
```

### 19. Разделение update и render

Полезно различать два типа функций.

#### Изменение состояния

```python
def update_order(dt):
    ...
```

Здесь изменяются:

- таймер;
- состояние заказа;
- координаты;
- другие данные симуляции.

#### Отрисовка

```python
def draw_scene(screen):
    ...
```

Здесь программа только показывает текущее состояние.

```
Важная договорённость

Функция draw_* не должна неожиданно уменьшать деньги,
менять остатки товара или завершать приготовление заказа.
```

Такое разделение станет основой дальнейшего модульного проектирования.

### 20. Рекомендуемая структура программы

На данном этапе достаточно одного файла, но код должен быть разделён на функции.

Например:

```python
def handle_events():
    ...

def handle_movement(dt):
    ...

def update_order(dt):
    ...

def draw_scene():
    ...

def draw_ui():
    ...

def main():
    ...
```

Основной цикл при этом остаётся компактным:

```python
while running:
    dt = clock.tick(60) / 1000.0

    # события
    # ввод
    # update
    # render
```

Полное разбиение проекта по отдельным модулям будет рассматриваться далее.
