# Практическая работа № 2 — «Симулятор пекарни. Этап 1 — клиент и заказ»

Интерактивное 2D-приложение на PyGame: клиент перемещается по залу пекарни,
оформляет заказ у прилавка, ожидает приготовления и получает заказ в зоне выдачи.

## Запуск

Требования: Python 3.8+, pygame 2.x.

```bash
pip install pygame
python main.py
```

## Управление

| Клавиша | Действие |
|---|---|
| `W`, `A`, `S`, `D` | движение клиента |
| `SPACE` | смена цвета клиента |
| `E` | взаимодействие: открыть меню / получить заказ / закрыть меню |
| `1`–`4` | выбор товара в меню |
| `ESC` | выход из программы |

## Основные программные решения

### 1. Главный цикл приложения (game loop)

Приложение построено вокруг цикла, который каждый кадр повторяет последовательность:

```text
события → ввод → обновление состояния → отрисовка → показ кадра
```

В коде (`main()`):

```python
while state["running"]:
    dt = clock.tick(FPS) / 1000.0
    handle_events(state)
    handle_movement(state, dt)
    update_order(state, dt)
    draw_scene(screen, fonts, state)
    draw_cooking_indicator(screen, fonts, state)
    draw_ui(screen, fonts, state)
    pygame.display.flip()
```

Закрытие окна выполняется по событию `pygame.QUIT` (крестик) и по нажатию `Esc`;
корректное завершение библиотеки гарантируется вызовом `pygame.quit()` в блоке `finally`.

### 2. Движение, независимое от FPS (delta time)

Скорость клиента задана в пикселях в секунду, а перемещение учитывает время кадра:

```python
dt = clock.tick(FPS) / 1000.0
position += direction * speed * dt
```

Благодаря этому реальная скорость клиента не зависит от фактической частоты кадров.

### 3. Диагональное движение

Вектор направления собирается из осей клавиатуры и нормализуется:

```python
if direction.length_squared() > 0:
    direction = direction.normalize()
```

Поэтому движение по диагонали не быстрее движения по одной оси.

### 4. Дискретные события и непрерывный ввод

- `pygame.KEYDOWN` — однократные действия: `SPACE` (смена цвета), `E` (взаимодействие),
  `1–4` (выбор товара), `ESC` (выход);
- `pygame.key.get_pressed()` — непрерывное движение, пока удерживаются `WASD`.

### 5. pygame.Rect: зоны, препятствия и область взаимодействия

Все зоны сцены описаны прямоугольниками `pygame.Rect`: вход, прилавок, касса, зона выдачи.
Прилавок и касса входят в список `OBSTACLES`.

Столкновения проверяются так: вычисляется предполагаемая новая позиция, для неё строится
прямоугольник клиента и проверяется `colliderect()` с препятствиями. Проверка выполняется
по осям раздельно (сначала X, затем Y), поэтому клиент может «скользить» вдоль препятствия,
а не застревать.

Перед прилавком расположена невидимая зона взаимодействия `COUNTER_INTERACTION_RECT`:
если прямоугольник клиента пересекает её, появляется подсказка «E — сделать заказ»;
вне зоны нажатие `E` меню не открывает.

### 6. Состояния заказа

Используется конечный набор состояний:

```text
NO_ORDER → WAITING → READY → DONE
NO_ORDER → READY   (товары без приготовления)
```

- хлеб и булочка сразу переходят в `READY`;
- сэндвич и кофе переходят в `WAITING` и становятся `READY` после завершения таймера;
- переход `READY → DONE` выполняется нажатием `E` в зоне выдачи;
- одновременно у клиента не более одного активного заказа: пока состояние `WAITING`
  или `READY`, новый заказ оформить нельзя.

### 7. Таймер приготовления без time.sleep()

Приготовление моделируется уменьшением оставшегося времени на каждом кадре
в функции `update_order()`:

```python
if state["order_state"] == WAITING:
    state["cook_time_left"] -= dt
    if state["cook_time_left"] <= 0:
        state["order_state"] = READY
```

Приложение при этом не останавливается: во время ожидания клиент двигается,
сцена перерисовывается, окно реагирует на закрытие.

### 8. Индикатор приготовления и полоса прогресса

В состоянии `WAITING` отображаются название товара, оставшееся время и полоса прогресса:

```python
progress = 1.0 - cook_time_left / cook_time_total
filled_width = int(bar_width * progress)
```

Полоса рисуется двумя прямоугольниками: фоновым и заполненной частью.
После завершения приготовления индикатор сообщает, что заказ готов.

### 9. Разделение обновления состояния и отрисовки

- состояние изменяют: `handle_events()`, `handle_movement()`, `update_order()`, `try_order()`;
- состояние только отображают: `draw_scene()`, `draw_ui()`, `draw_menu()`,
  `draw_cooking_indicator()`.

Логика денег, остатков товаров и состояний заказа не выполняется внутри функций `draw_*`.

### 10. Организация программы

Программа содержит функцию `main()` и отдельные функции `handle_events()`,
`handle_movement()`, `update_order()`, `draw_scene()`, `draw_ui()`, а также вспомогательные
(`draw_menu()`, `draw_cooking_indicator()`, `draw_zone()`, `can_order()`, `can_pickup()`,
`try_order()`). Всё состояние приложения собрано в словарь `state`, который передаётся
в функции аргументом, поэтому данные не разбросаны по глобальным переменным.
