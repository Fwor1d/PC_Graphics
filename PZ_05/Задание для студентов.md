# Практическая работа № 5
## Интерактивный редактор аффинных преобразований в PyGame
 
**Продолжительность:** 2 пары

---

## 1. Цель практической работы

Разработать интерактивное графическое приложение, в котором пользователь управляет **аффинными преобразованиями двумерного объекта**, а координаты вершин вычисляются через **матрицы 3×3**.

В результате выполнения работы необходимо научиться:

- задавать векторную фигуру в локальной системе координат;
- представлять вершины в однородных координатах;
- выполнять перенос, масштабирование, поворот, отражение и shear средствами NumPy;
- объединять преобразования матричным умножением;
- демонстрировать зависимость результата от порядка операций;
- поворачивать объект вокруг произвольной опорной точки (`pivot`);
- переводить координаты мыши из экранной системы в локальную через обратную матрицу;
- отделять математическую модель от графического представления в PyGame.

---

## 2. Общая постановка задачи

Необходимо разработать приложение **Affine Transform Studio** — интерактивный редактор двумерных аффинных преобразований.

Пользователь должен иметь возможность изменять положение, размеры, ориентацию и форму геометрического объекта с помощью клавиатуры и мыши.

Основной объект — несимметричная составная фигура «домик», состоящая из нескольких многоугольников.

Приложение должно одновременно отображать исходную геометрию, преобразованный объект, текущие параметры и результирующую матрицу преобразования.

### Пример интерфейса

```text
┌─────────────────────────────────────────────────────────────────────┐
│ AFFINE TRANSFORM STUDIO                                             │
│                                                                     │
│   РАБОЧАЯ ОБЛАСТЬ                      ПАРАМЕТРЫ И МАТРИЦА          │
│   ┌──────────────────────────────┐    ┌─────────────────────────┐   │
│   │ сетка, оси X/Y               │    │ Position: tx, ty        │   │
│   │                              │    │ Rotation: angle         │   │
│   │ исходный контур              │    │ Scale: sx, sy           │   │
│   │    · · · ·                   │    │ Shear: kx, ky           │   │
│   │                              │    │ Reflection: X / Y       │   │
│   │      преобразованный         │    │ Pivot: px, py           │   │
│   │      объект                  │    │                         │   │
│   │         ● pivot              │    │  [ m00 m01 m02 ]        │   │
│   │                              │    │  [ m10 m11 m12 ]        │   │
│   │                              │    │  [ m20 m21 m22 ]        │   │
│   └──────────────────────────────┘    └─────────────────────────┘   │
│                                                                     │
│  УПРАВЛЕНИЕ: стрелки, Q/E, Z/X, A/D, H/V, J/L, U/O, P+ЛКМ, M, R     │
└─────────────────────────────────────────────────────────────────────┘
```

Схема условная. Допускается иной дизайн интерфейса при сохранении всех обязательных функций.

## 3. Обязательные задания

### Задание 1. Создание графического приложения

Создать окно PyGame.

Необходимо:

1. Установить заголовок окна.
2. Создать главный цикл приложения.
3. Отобразить координатную сетку и оси X/Y.
4. Разделить окно на рабочую область и информационную панель.
5. Определить начало координат рабочей области.
6. Реализовать закрытие окна и выход по `Esc`.
7. Использовать `pygame.time.Clock()` для управления частотой кадров.

### Задание 2. Создание геометрического объекта

Создать составную несимметричную фигуру (придумайте самостоятельно, например "домик") минимум из трёх многоугольников:

1. корпус;
2. крыша;
3. дверь или окно, расположенное несимметрично.

Требования:

- вершины каждого многоугольника хранить в массиве NumPy;
- использовать локальную систему координат объекта;
- каждый многоугольник может иметь собственный цвет;
- исходная геометрия должна оставаться неизменной;
- исходный объект отображать нейтральным контуром;
- преобразованный объект отображать другим цветом.

Не допускается замена геометрической фигуры заранее подготовленным PNG-изображением.

### Задание 3. Реализация базовых матриц преобразований

В отдельном модуле реализовать функции:

```python
translation(tx, ty)
scale(sx, sy)
rotation(angle_degrees)
```

Каждая функция должна возвращать матрицу NumPy размером **3×3**.

Требования:

1. Использовать тип данных `float`.
2. Представлять точки в однородных координатах.
3. Применять матричное умножение `@`.
4. Обеспечить независимое изменение `tx`, `ty`, `sx`, `sy` и угла.
5. Не перезаписывать исходные вершины при каждом преобразовании.
6. Не допускать нулевого масштаба. Рекомендуемый диапазон — `[0.2; 4.0]`.

Для отрисовки использовать `pygame.draw.polygon()` с координатами, вычисленными через NumPy.

### Задание 4. Интерактивное управление объектом

Реализовать управление параметрами в реальном времени.

Рекомендуемый набор клавиш:

| Действие | Клавиши |
|---|---|
| Перенос объекта | Стрелки |
| Поворот | `Q` / `E` |
| Масштабирование по X | `Z` / `X` |
| Масштабирование по Y | `A` / `D` |
| Сброс преобразований | `R` |
| Выход | `Esc` |

При удержании клавиш перемещение и непрерывное вращение должны учитывать `dt`, чтобы скорость не зависела от FPS.

Параметры изменяются в логике обновления приложения, а отрисовка только отображает их текущее состояние.

### Задание 5. Отображение параметров и результирующей матрицы

Создать информационную панель.

Отображать:

- текущие `tx`, `ty`;
- угол поворота в градусах;
- масштаб `sx`, `sy`;
- коэффициенты `shear X` и `shear Y`;
- состояние отражения;
- координаты pivot;
- выбранный порядок композиции;
- результирующую матрицу 3×3;
- подсказки по управлению.

Значения матрицы выводить построчно минимум с двумя знаками после запятой.

При изменении любого параметра отображаемая матрица должна обновляться.

Округление допускается только при выводе значений, а не при выполнении математических вычислений.

### Задание 6. Композиция и порядок преобразований

Реализовать объединение преобразований в одну результирующую матрицу.

Предусмотреть два режима:

**Режим A — поворот, затем перенос:**

```python
M = T @ R
```

**Режим B — перенос, затем поворот:**

```python
M = R @ T
```

Переключение режимов можно реализовать клавишей `M`.

Текущий режим должен отображаться в интерфейсе.

Для демонстрации разницы необходимо предусмотреть состояние, при котором:

- `sx = sy = 1`;
- `shear = 0`;
- отражения выключены;
- `pivot = (0, 0)`.

Обязательный проверочный пример:

Исходная точка `(20, 0)`, перенос `(120, 60)`, поворот `+90°`.

Ожидаемые результаты:

| Режим | Результат |
|---|---|
| `T @ R` | `(120, 80)` |
| `R @ T` | `(-60, 140)` |

### Задание 7. Поворот вокруг произвольной точки (pivot)

Реализовать вращение относительно заданной опорной точки.

Требования:

1. Начальное значение pivot — `(0, 0)` в локальных координатах.
2. Пользователь должен иметь возможность изменить pivot мышью через `P + ЛКМ`.
3. Экранные координаты выбранной точки необходимо перевести в локальные.
4. Использовать композицию:

```python
M_pivot = T_positive @ R @ T_negative
```

где `T_positive` — перенос на `+pivot`, а `T_negative` — перенос на `-pivot`.

5. Отображать pivot отдельным маркером.
6. При повороте расстояния от pivot до вершин должны сохраняться.

Локальное вращение вокруг pivot и общий перенос объекта необходимо реализовать как отдельные операции.

### Задание 8. Отражение и shear

Добавить следующие преобразования:

- отражение относительно локальной вертикальной оси;
- отражение относительно локальной горизонтальной оси;
- горизонтальный shear;
- вертикальный shear.

Рекомендуемые клавиши:

| Действие | Клавиши |
|---|---|
| Отражение относительно вертикальной оси | `H` |
| Отражение относительно горизонтальной оси | `V` |
| Изменение shear X | `J` / `L` |
| Изменение shear Y | `U` / `O` |

Рекомендуемый диапазон для коэффициентов shear: `[-0.8; 0.8]`.

Необходимо обеспечить обратимость итоговой матрицы при допустимых значениях параметров.

Все операции должны включаться в общую матричную композицию.

### Задание 9. Выделение объекта мышью через обратную матрицу

Реализовать выбор преобразованного объекта обычным щелчком ЛКМ.

Последовательность действий:

1. Получить экранные координаты курсора.
2. Вычислить общую матрицу преобразования «локальные координаты → экранные координаты».
3. Вычислить обратную матрицу.
4. Перевести координаты курсора в локальную систему объекта.
5. Проверить попадание полученной точки в исходные многоугольники.
6. Изменить визуальное состояние выбранного объекта.

Проверка попадания должна выполняться по геометрическому силуэту.

**Не допускается** считать объект выбранным только потому, что курсор находится внутри его ограничивающего `pygame.Rect`.

Если матрица необратима, программа должна корректно обработать это состояние без аварийного завершения.

### Задание 10. Проверка корректности

Реализовать и выполнить проверку основных математических и графических операций.

Обязательные сценарии:

1. Исходное состояние объекта без преобразований.
2. Перенос с сохранением формы.
3. Поворот на 90°, 180° и 360°.
4. Масштабирование `sx=2`, `sy=0.5`.
5. Двойное отражение возвращает исходную ориентацию.
6. Горизонтальный shear преобразует прямоугольник в параллелограмм.
7. Переключение `T @ R` и `R @ T` изменяет результат.
8. Pivot остаётся неподвижным относительно выполняемого вокруг него вращения.
9. Щелчок внутри повернутого объекта выделяет его.
10. Щелчок по пустой области ограничивающего прямоугольника не выделяет объект.
11. Сброс восстанавливает исходные параметры.
12. Многократная смена преобразований не приводит к накоплению геометрических искажений.

## 4. Требования к архитектуре проекта

Минимальная структура:

```text
transform_editor/
├── main.py
├── transformations.py
├── objects.py
├── renderer.py
├── settings.py
```

Назначение модулей:

| Файл | Ответственность |
|---|---|
| `main.py` | Окно, события, `dt`, управление режимами |
| `transformations.py` | Создание и композиция матриц, преобразование точек, обратная матрица |
| `objects.py` | Исходные многоугольники, параметры и состояние выделения |
| `renderer.py` | Сетка, оси, полигоны, pivot, информационная панель |
| `settings.py` | Размеры, цвета, ограничения параметров и скорости |

**Обязательное архитектурное требование:** модуль `transformations.py` не должен импортировать PyGame.

Математические операции должны быть доступны для тестирования отдельно от графического приложения.
